# Финализация браузера истории и Safe Scan

Итог на 10 октября 2026 года: Guardian получил встроенный браузер для EVM dApp, восстановленную историю операций через Ankr и чтение разрешений токенов без зависимости от приостановленного Moralis. Ошибка чтения больше не показывается как отсутствие рисков. Изменения входят в один финальный коммит; ключи, APK и локальные журналы остаются вне Git.

## Браузер и подпись

Браузер доступен из настроек и через `ibitiguard://browser?url=…`. Он принимает HTTPS, показывает домен вне содержимого сайта и предоставляет один EIP-1193 провайдер с обнаружением EIP-6963. Схема Privy `ibitiguardian://` не заменяется. WalletConnect WalletKit в этот набор не входит.

Подключение сайта требует отдельного согласия пользователя. Разрешение привязано к origin и аккаунту, хранится в защищённом хранилище на 30 дней и может быть отозвано. Подключение не разрешает подпись автоматически. Навигация, закрытие страницы, смена аккаунта, блокировка кошелька и отзыв доступа делают незавершённый запрос неактуальным.

Для транзакций используются существующий Privy signer, Policy/EPK, проверка исполнения и газа, нативный preview и подтверждение PIN или биометрией. Запрос повторно проверяется перед подписью. Неизвестная сеть, недопустимый метод, изменившийся аккаунт, превышение лимита или ошибка проверки закрывают запрос. Permit и другие неподдерживаемые разрешения расхода через typed data блокируются.

Получение выплаты из проверенного семейства контрактов LVS имеет узкую дополнительную проверку: точный ABI, отпечатки runtime bytecode и связанных контрактов, актуальная симуляция поступления токенов и одноразовое согласие на показанный запрос. Сайт, название метода или нулевой native value не могут сами создать это доказательство. Evidence привязано к calldata, аккаунту, сети и gas-inclusive payload, ограничено по времени и не изменяет пользовательскую политику. Это не универсальное разрешение произвольного вызова контракта.

Интерфейс нового браузера пока имеет русский и английский варианты; для других языков используется английский. Экраны истории и финальные формулировки сканирования переведены на все 17 языков приложения.

## История операций

`TxHistoryService` выбирает Ankr, затем доступный Moralis. Продолжение списка остаётся привязанным к исходному провайдеру. Ошибка источника не становится пустой историей.

Native-транзакции и token transfers имеют независимые курсоры. Объединённая страница не обрезается до размера одной исходной страницы. Поздние движения токенов дополняют ранее загруженную операцию; строки объединяются по hash без повторов. Фильтр позволяет загрузить следующие страницы, даже если на текущей нет подходящих операций.

Тап по операции открывает детали, включая отправителя, получателя, сумму, статус, время, hash, известную комиссию и ссылку на explorer. Комиссия указана только когда есть данные о её оплате этим кошельком. Вопросы ассистента об истории используют тот же фасад чтения.

## Safe Scan и состояние при ошибке

При настроенном Ankr сканирование проходит через `AnkrApprovalSource`. Источник получает все страницы ERC-20 Approval событий владельца, дополняет свежий хвост RPC-логами и читает фактический `allowance(owner, spender)` на одном актуальном блоке. Отозванные и израсходованные разрешения исключаются. Событие из истории само по себе не доказывает активное разрешение.

Проверяются сеть, фильтры логов, синхронизация индексатора, свежесть блока, пагинация и неизменность проверяемого блока. Неполные данные, устаревший источник, ошибка allowance, предел страниц или пар закрываются ошибкой, а не частичным успешным результатом. При отсутствии Ankr остаётся существующий Moralis fallback; отказ настроенного Ankr не маскируется переходом к другому источнику.

Таймаут одного Ankr read запроса составляет до 20 секунд, общий бюджет сканирования — 60 секунд. Временные сетевые ошибки, HTTP 408/429/5xx и распознанные временные RPC ошибки допускают максимум три попытки конкретного чтения в том же общем бюджете. После таймаута старый HTTP client закрывается перед заменой. Ошибки доступа, схемы и обязательного contract read не принимаются за пустой результат.

При неудаче Safe/Panic модалка показывает ошибку и возможность повторить сканирование. Она не показывает «Рисков нет», «Завершено» или экран отзыва разрешений. Повторное нажатие не создаёт второй scan; закрытая модалка игнорирует позднее завершение. Фоновая проверка сохраняет прежние риски неудавшейся сети и не обновляет время последнего успешного сканирования при неполном результате.

`scannedCount` означает количество найденных активных пар token/spender, а не количество контрактов или RPC запросов. Поэтому экран использует «Активных разрешений токенов» и кнопку «Понятно». Ноль означает отсутствие активных разрешений в рамках проверки выбранной сети, а не абсолютную безопасность кошелька. NFT operator approvals, Permit2 и все возможные риски кошелька эта ERC-20 проверка не покрывает.

Исправление сканирования не меняет существующие методы переводов, swap, подписи, revoke, transaction queue или финансового исполнения. Отдельные изменения signer и Policy в этом коммите относятся к ранее реализованному браузерному пути и его request-scoped проверкам.

## Проверки

Финальный Flutter suite: 542 PASS, два opt-in сетевых probe пропущены. JavaScript мост: 9 PASS. Safe Scan, его модалки и локализация: 73 PASS. Анализ новых компонентов чистый; project-wide baseline содержит 201 issue и ноль compile errors. Один прежний информационный issue в тесте истории исправлен.

Финальный Android debug APK успешно собран после уточнения переводов. На телефоне установлена предыдущая проверенная debug-сборка; новые подписи счётчика войдут при следующем обновлении. В этой финализации повторная установка, закрытие приложения и очистка данных не выполнялись. iOS и desktop сборки в этот прогон не входят.

До финализации выполнен read-only BSC probe: шесть HTTP 200, успешное чтение index/RPC/current allowance, ноль активных разрешений, latency 725 ms. История также прошла отдельное чтение с реальной пагинацией. Пользователь подтвердил историю и показал на телефоне успешный Safe Scan. В ходе этой финализации новые живые подписи, переводы или отзывы не выполнялись.

```powershell
flutter test
node --test test/services/dapp/guardian_provider_test.cjs
flutter analyze
git diff --check
```

Сетевые probe запускаются только явно: `RUN_ANKR_HISTORY_PROBE=true` или `RUN_ANKR_APPROVAL_PROBE=true`, плюс `ANKR_PROBE_WALLET_ADDRESS` с выбранным оператором публичным адресом. Ключ читается из локального игнорируемого `secrets/ankr.json`; адрес не зашивается в тесты. Журналы probe содержат только статусы, счётчики и задержку, без raw response, ключей, адресов и сумм.

Moralis остаётся внешним ограничением: во время диагностики его бесплатный доступ отвечал отказом. Перенос истории и approvals на Ankr не означает восстановления остальных Moralis metadata/price API и не предполагает покупки платного тарифа.
